## 问题

项目应如何组织两条研究路线的关系？哪些边界条件需要在架构层面锁定？

## 考虑过的方案

1. **单一路线端到端**：4×4 光电阵列 → 采集 → 28×28 CNN → 分类，所有子系统必须实时联通
2. **双路线松耦合**：两条路线在研究主题上相关，但当前工程阶段不要求实时数据接口
3. **完全独立项目**：将两部分作为独立项目管理，不共享仓库和文档

## 选择

**方案 2：双路线松耦合。** 路线 A（光电突触阵列信号采集与光功率重建）和路线 B（类脑 CNN 训练研究与 FPGA 推理部署）作为同一项目下的两个独立方向，各自有独立的输入、输出、验证方式和开发进度。

## 原因

1. **解耦风险**：器件接口未知不阻塞路线 B 的训练研究和 FPGA 推理开发
2. **明确交付**：每条路线有独立可验证的完成标准
3. **研究完整性**：两条路线各自有独立的研究价值和发表潜力
4. **避免虚假承诺**：不要求构建"光学输入 → 分类输出"的端到端系统，避免被任意环节阻塞
5. **资源并行**：可独立推进，互不等待

## 关键边界决策

### 决策 1：为什么工程基线采用带偏置读取

课题组论文表明器件可在极小/接近零偏置下产生光电流，但零偏置读取在实际工程中不稳定。因此工程基线采用可控或可配置偏置。具体偏置值待实物测量后确定。

### 决策 2：为什么采样率必须可配置

器件稳态时间和最低采样率尚无确定数值。1 kHz 只能作为早期实验的起始默认值。第一版必须支持采样周期、等待时间、采样数量、平均窗口等参数的可配置，以便在获得实物后灵活调整。

### 决策 3：为什么先建立标准梯度下降基线

标准反向传播是 CNN 训练的确定基线，提供可复现的准确率参考点。在此基础上研究类脑更新规则，才能区分性能变化来自规则本身还是网络结构。没有基线的类脑研究无法进行有意义的评估。

### 决策 4：为什么 FPGA 只推理而不训练

Cyclone IV 资源有限，不适合部署反向传播所需的梯度计算和参数更新逻辑。训练完全在 PC 端离线完成，FPGA 只加载最终权重执行前向推理。这一分工降低了 FPGA 逻辑复杂度，也使得训练和推理可以独立迭代。

### 决策 5：为什么当前不要求端到端耦合

两条路线的数据尺寸（4×4 vs 28×28）和数据类型（光功率矩阵 vs 灰度图）不同，强行要求实时端到端连接需要引入插值或上采样等额外处理，且 4×4 阵列仍在制作中。不要求耦合避免了两条路线互相阻塞。

## 未来可修订的决策

以下决策未来可根据实验进展修订：

1. 采样率配置范围和默认值——需实物测量后更新
2. 偏置电压具体值——需实验确定
3. 光功率经验模型——需拟合后确定
4. 类脑更新规则数学形式——需实验收敛
5. 是否需要逐像素标定——需一致性数据
6. 两条路线是否及如何建立算法层联系——远期选项

## 后果

- 所有文档按双路线结构组织
- 不在任何文档中描述"端到端实时系统"为当前阶段目标
- FPGA 在两条路线中承担不同角色，需分别文档化
- 路线 B 可不受器件条件限制独立推进
- 路线 A 的模拟电路设计保留为尚未锁定的状态

## 后续更新（2026-08-02，见 ADR 008）

- 路线 A 必须支持**多次采样与动态曲线记录**（原始交付为带时间戳响应序列）；光功率估计仅在明确测量协议下成立；"约 20 秒到 1 分钟达到稳态"为会议初步估计，待实测。
- 路线 B 新增**器件模型驱动训练**方向（RGB → 电导/电流表示）、**定向 Hebbian**、**KAN**。
- 双路线"完全无数据联系"更新为：实时联调不强制，但**允许并需要离线算法耦合**。
- 已完成 MNIST/FPGA 数字基线保留为已完成工程基线。
