# ADR 001：当前硬件边界为 4×4

| 字段 | 值 |
|------|-----|
| **状态** | Accepted |
| **提出日期** | 2026-07-19 |
| **最后更新** | 2026-07-19 |

## 问题

当前项目的硬件范围和任务定义应以多大的阵列为边界？

## 考虑过的方案

1. **以 4×4 为边界**：当前实物为 4×4，所有任务必须能在此硬件或模拟数据上验证
2. **以未来大阵列为前提**：先按理想大系统设计，等未来更大阵列
3. **不设边界**：灵活处理，视情况而定

## 选择

**方案 1：以 4×4 为现实边界。**

## 原因

1. 项目负责人已确认 4×4 是当前唯一实物
2. 未来阵列的时间和规模不确定
3. 以大阵列为前提会导致过早锁定资源需求，分散第一阶段焦点
4. 4×4（16 单元）已经能支持有限但有意义的实验（简单图案、颜色分类、时序编码验证）

## 后果

- 设计决策不以"未来更大阵列"为前提
- 当前任务必须能在 4×4 或同等规模模拟数据上验证
- 如果未来获更大阵列，M0–M1 的工作（软件基线、FPGA 推理、输入方案分析）仍然有效
- 需明确 4×4 能做什么、不能做什么
- 不能回避 4×4 与标准数据集（如 MNIST 28×28）之间的差距
