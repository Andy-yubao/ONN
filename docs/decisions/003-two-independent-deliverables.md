# ADR 003：项目有两个独立交付方向

| 字段 | 值 |
|------|-----|
| **状态** | Accepted |
| **提出日期** | 2026-07-19 |
| **最后更新** | 2026-07-19 |

## 问题

当前项目应组织为一个端到端链路，还是两个独立的交付方向？

## 考虑过的方案

1. **单一端到端链路**：4×4 器件 → 外围电路 → FPGA CNN → 手写数字识别
2. **两条独立主线**：A. 4×4 采集系统 + B. 28×28 FPGA CNN；二者各自独立交付
3. **柔性混合**：部分连接，视情况调整

## 选择

**方案 2：两条独立主线。** 4×4 外围采集系统和 28×28 CNN FPGA 推理作为两个独立交付方向，当前不要求端到端物理连接。

## 原因

1. 器件接口（pinout、电气规格）未知，若依赖此信息会阻塞 FPGA 推理的开发
2. 两条主线解耦可降低项目风险，任意一条的延迟不影响另一条
3. 每条主线有独立可验证的完成标准，交付物更明确
4. 4×4 太小不再构成"与 28×28 输入矛盾"——因为不是同一主线的输入输出
5. 便于资源并行推进

## 后果

- 文档全部按 A/B 两组组织
- 不再以"端到端系统联调"为成功标准
- 器件曲线作为辅助研究（C 轨），不阻塞 A/B
- 未来若条件成熟，可在算法层建立离线弱联系
