# 需求文档

> **当前状态**：M0 阶段。需求按三组编号——A 组为 4×4 外围采集，B 组为 FPGA CNN 推理，C 组为辅助器件曲线建模。A/B 为固定交付，C 不阻塞 A/B。
>
> A 组性能要求为派生要求，不写死未经验证的数值。

---

## A 组：4×4 外围采集系统

### A-Fxx：功能需求（Functional）

| 编号 | 需求描述 | 验收标准 | 优先级 |
|------|---------|---------|--------|
| A-F01 | 安全 pinout 确认前不连接任何电源或信号 | 安全清单已审核，禁止通电规则已文档化 | P0 |

| A-F03 | 支持至少一种模拟读出方式，将器件输出转换为可量化电压 | 确认读出电路工作正常，输出在 ADC 输入范围内 | P0 |
| A-F04 | 完成模数转换，输出数字值 | ADC 输出可被控制器读取 | P0 |
| A-F05 | 支持多档采样（至少两档逻辑模式） | 可在常规采样和高速采样之间切换 | P0 |
| A-F06 | 保留带时间戳的原始 ADC 数字序列 | 数据文件包含时间戳和原始 ADC 码 | P0 |
| A-F07 | 支持长时连续监测（秒至小时级） | 可配置记录时长，连续保存数据 | P0 |
| A-F08 | 经标定后可换算为电压或电流 | 标定文件 + 转换脚本，结果可验证 | P1 |

### A-Pxx：性能需求（Performance，派生要求）

> 以下数值由器件有效响应时间、模拟带宽、MUX 建立时间、ADC 吞吐率和数据传输能力派生。**未经过论证前不写死具体数字。**

| 编号 | 需求描述 | 验收原则 | 优先级 |
|------|---------|---------|--------|
| A-P01 | **总采样率**应使最快待提取特征内有足够有效采样点 | 派生值 ≥ 特征带宽 × 采样系数 | P1 |
| A-P02 | 明确区分**总采样率**与**单通道有效采样率** | 文档记录计算公式和开销 | P1 |
| A-P03 | 若使用 ADC + MUX 多通道，考虑 MUX 建立时间、ADC 采样保持、丢弃首样、控制传输开销 | 实际单通道采样率 ≤ ADC 标称采样率 / 通道数 | P1 |
| A-P04 | 模拟带宽、位宽、存储容量由信号特征和实验时长决定 | 文档记录推导过程 | P2 |
| A-P05 | 高频能力同时受模拟带宽、噪声、分辨率、零漂、数据量、温漂、时间戳和连续运行稳定性约束 | 性能报告包含上述项评估 | P2 |

#### 三种逻辑采样模式（不写死数值）

| 模式 | 用途 | 核心要求 |
|------|------|---------|
| **快速瞬态** | 光照开关、短脉冲、峰值、上升下降 | 最高采样率，捕获瞬态细节 |
| **常规曲线** | 一般响应、重复刺激、稳态 | 中等采样率，平衡数据量与时间分辨率 |
| **长时监测** | 衰减、保持、恢复、漂移 | 低速连续记录，长时间运行稳定性 |

## 接口需求

详见 [interface_specification.md](interface_specification.md)。接口分三组：

- **A 类接口**：光源→器件→读出→ADC→控制器→PC（数据采集链）
- **B 类接口**：Python→FPGA（训练→推理）
- **C 类接口**：器件曲线→Python 模型（离线算法联系）

> 当前不存在"4×4 外围电路 → FPGA CNN"的正式系统接口。
